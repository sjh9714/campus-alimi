# 2026-10-26 화면·로그인·검수 확인

4단계 완료 기준은 "휴대폰 크기에서 로그인 없이 공지·혜택을 보고, 로그인 후 저장이 됨"이었다. 390×844 뷰포트의 Chromium(Playwright)으로 실제 서버에 붙여 확인했다.

## 환경

- API `ADMIN_EMAIL=<관리자 이메일> API_URL=http://localhost:8080 ./gradlew bootRun`, 메일은 console 모드
- 화면 `NEXT_PUBLIC_API_BASE=http://localhost:8080 npm run dev`
- DB는 같은 날 실제 수집 결과(학사일정 49건, 공지 62건)

## 한 일과 본 것

| 순서 | 한 일 | 본 것 |
|---|---|---|
| 1 | `/` 로그인 없이 열기 | 일정 목록이 뜸. 하단 탭 일정·혜택·설정. 저장 버튼 없음 |
| 2 | `/settings/` 에서 이메일 입력 후 제출 | "메일을 보냈습니다" 안내. API 로그에 링크가 찍힘 |
| 3 | 링크 열기 | 쿠키가 심기고 `/?login=ok` 로 돌아옴. 저장 버튼과 검수 탭이 생김 |
| 4 | `/admin/` | 검수 전 공지 62건. 첫 공지(인송장학생)의 항목 둘과 원문 링크, 첨부 이름 |
| 5 | 첫 항목 고치기. 학년 전체, 학과 ALL, 조건 한 줄 입력 후 저장 | 항목이 "확인됨 · 전체 학년"으로 바뀜. DB `date_item.status=REVIEWED, reviewed_by=<관리자 이메일>` |
| 6 | 검수 완료 | 목록이 61건으로 줄고 DB `notice.status=REVIEWED` |

## 확인하다 고친 것

- 홈에 "위령의 날", "교수회의", "수업일수 3/4"가 올라와 있었다. 돈·학적과 무관한 학사일정이라 수강·등록·휴학·복학·성적·장학·졸업·계절학기·납부·학위수여·개시일만 남기도록 걸렀다. 성심 48건 중 남는 것은 20건 안팎이다.
- 학사일정 항목에 "검수 전"이 붙어 있었다. 표를 읽은 것이라 파싱이 없으니 처음부터 확인된 상태로 둔다.
- 메일 링크가 `http://localhost:3000/api/...` 를 가리켰다. 로컬은 화면(3000)과 API(8080)가 다르다. `api-url` 설정을 추가했고 운영에서는 비워 두면 같은 origin이다.
- 콘솔에 로그인 전 `/api/me` 401이 찍힌다. 의도한 동작이라 두되, 운영 로그를 볼 때 혼동하지 않도록 여기 적어 둔다.

## 하지 않은 것

- 실제 휴대폰에서는 아직 열지 않았다. 배포 뒤 6단계에서 한다.
- Gmail SMTP 발송은 앱 비밀번호가 있어야 해서 아직 시험하지 않았다.
- 웹푸시는 5단계.
