# 2026-10-26

## 계획

- 생각등대 최신 영상 7편과 2026년 학생 서비스 흐름을 조사했다. 기준은 "포트폴리오 5개보다 운영한 서비스 1개, 사용자 10명".
- 후보를 세 번 냈고 전부 반려됐다. 반려 이유는 순서대로 "겹치는 아이디어", "예시를 주제로 받지 말 것", "모르는 사람과 만나게 하는 기능은 안 됨", "백엔드 문제가 아니라 서비스를 먼저".
- 네 번째에서 "학생에게 돈이 되는 정보를 정확하게만" 방향이 정해졌다. 학교 장학 공지 수집과 학생 혜택 체크리스트를 합친다.
- 가톨릭대 공지 게시판(분류 일반 20, 학사 21, 장학 22, 취창업 23), 학사일정 표가 공개임을 확인했다.
- 이름은 캠퍼스 알리미(campus-alimi)로 확정.

## 승인

- 계획 전문 `~/.claude/plans/synthetic-snuggling-fern.md`
- ADR 001~008 승인. 002는 수집원을 셋(학사일정 표 주력, 공지 장학·학사)으로 넓혔고, 003은 공지 하나에 날짜 항목 여럿과 이미지 전용 공지의 수동 입력을 더했고, 008(프로필·대상 태그)을 추가했다.

## 구현 (2단계)

- Spring Boot 3.4 + PostgreSQL + jsoup. 수집기 둘, 날짜 파서, 항목 추출기, Flyway V1, 한 번 돌리고 끝나는 RUN_ONCE.
- 자동 테스트 23개. 학교 페이지 7장을 픽스처로 저장. Testcontainers는 1.21.4로 올려야 최신 Docker와 맞았다.
- 실제 사이트 수집 결과와 고친 규칙은 `docs/verification/2026-10-26-collector.md`.

## 구현 (3단계)

- 혜택 목록 `src/main/resources/benefits.yml` 15개. 공식 페이지를 직접 열어 확인한 것만. 작성자가 확인하고 링크를 남겼다.
- 범위 결정. 사용자가 "청년까지 묶으면 범위가 너무 커진다"고 해서 나이 기준 혜택 4개를 뺐다.
- `BenefitSeedFile` 이 규칙 위반을 거부하고, `BenefitSeeder` 가 앱 시작 시 DB에 맞춘다. 기록은 `docs/verification/2026-10-26-benefits.md`.

## 리뷰 (별도 세션, 코드 수정 없이 보고만)

리뷰 세션이 17개를 짚었다. 구현 세션이 다시 확인해 전부 맞다고 판단하고 고쳤다.

| 지적 | 고친 것 |
|---|---|
| 같은 빈 안에서 `@Transactional` 메서드를 직접 불러 트랜잭션이 안 걸림. 혜택 갱신·비활성이 DB에 안 남고, 공지 저장이 세 번의 개별 커밋 | 저장을 `NoticeStore`, `ScheduleStore`, `BenefitStore`로 분리. 읽기는 트랜잭션 밖, 저장은 한 트랜잭션 |
| 표 한 행의 날짜 열 여러 개를 하나로 합쳐 마감이 늦춰짐 (신청기간 10.30이 결과발표 11.20으로) | 열마다 따로 항목. 머리글이 없어 열 이름을 모르면 검수로 |
| 단일 날짜의 시각이 시작 시각에 들어가 마감 시각이 빔 | 시각이 하나면 마감 시각 |
| 학사일정 키에 날짜가 들어가 학교가 날짜를 고치면 옛 항목이 남음 | 키를 `연도:제목#n`으로, 이번에 안 보인 자동 항목은 삭제 |
| 공지 하나가 실패하면 그 뒤 전부 멈춤 | 글 단위 try/catch, 실패 글은 PARSE_FAILED로 검수 큐에 |
| 실패 fetch_log가 트랜잭션과 함께 롤백 | 읽기를 트랜잭션 밖으로 빼서 해결 |
| "평점 2.5 ~ 3.5"를 날짜로 읽음 | 점 구분 쌍에 요일·연도·일이 없으면 소수. "이상·점·%" 뒤따르면 버림 |
| "2024학년도"가 4학년으로 | `학년(?!도)`. "2~4학년"은 모름 |
| 연도가 뒤에만 있는 범위, 역순 범위, "까지" 월.일 | 각각 처리 |
| 목록의 등록일을 제목 날짜에서 읽을 수 있음 | 뒤쪽 칸에서 찾음 |
| 혜택 검증 빈틈(미래 확인일, ends_on < verified_on), activeFlag 어색함 | 검증 추가, `deactivate()`로 정리 |
| ADR 002 "분당 1회"와 설정 1.5초 불일치 | ADR을 실제 값으로 고침 |

고치지 않은 것. colspan 머리글(픽스처에 없음), 통합 테스트 세 메서드가 DB를 공유(각 메서드가 자기 데이터만 보도록 작성).
